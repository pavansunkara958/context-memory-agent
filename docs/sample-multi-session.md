# Sample Multi-Session Interaction

One investigation, three days, three separate sessions. Each session builds a
new `Agent` object with a different session id — **nothing is carried in
process state**. Everything day 2 and day 3 know came out of long-term memory
and the session store.

Generated by `python -m src.main demo --fresh`, running on the **hash embedding
backend** and the **extractive answerer** — no API key, no model download. The
answer *prose* is therefore blunt; the memory behaviour, routing decisions and
context accounting are exactly what the system does. Install
`sentence-transformers` and set `PROVIDER` for fluent answers over the same
pipeline.

## Continuity, stated plainly

Day 2 and day 3 were separate processes with separate session ids. Neither read
day 1's transcript. What they loaded upfront came from two places:

- **Long-term memory** — the four promoted facts, retrieved semantically
  against the open task.
- **Session store** — preferences (user-scoped) and task progress
  (`last_progress()` carries the most recent task across session boundaries).

The engineer was never asked again for their site, their firmware version, their
units, or what they were working on. That is the whole point of the tier split:
those four things are small and always relevant, so they load upfront; the
27-document knowledge base is large and conditionally relevant, so it loads
just in time and only when the gate opens.

## Cost of continuity

The upfront pack is ~111 tokens. A full turn with retrieval runs 450–1700
context tokens depending on how much survives optimisation. Carrying identity
across sessions costs roughly **7% of one turn's context** — which is why it can
be loaded unconditionally, every session, without thinking about it.
